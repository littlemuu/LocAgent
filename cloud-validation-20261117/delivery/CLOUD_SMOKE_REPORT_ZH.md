## 发现和处理的问题

1. Astropy基线重建失败：原仓库已跟踪的7个C/构建文件同时匹配.gitignore；删除历史再建基线时普通git add拒绝。已改为仅对原git ls-files明确列出的文件使用git add -f，未扩大到未知文件。两题都验证初始diff为空，随后编辑、测试、导出新文件diff通过。旧v2失败状态原样保留；得到用户确认后建立v3独立Astropy补跑。
2. 普通文本终答不兼容：Astropy B第14次编码响应finish_reason=stop，包含正常完成说明，并非length截断；当前适配器只接受tool_calls，因此误归入笼统的missing_tool_or_truncated_response。这是仍需处理的适配器兼容问题，本轮未改变终答契约后再次付费重跑。已保存非空预测文件，独立harness结果仅作为链路证据；不改写Agent失败日志。
3. Sympy A/B均在40次编码请求内主要反复诊断，未编辑源码。没有据此修改提示、检索或预算，也没有解读两组修复率。
4. 自动审批最初阻止向云端复制API凭据；用户明确授权后才传输。随后用户又明确允许一次Astropy补跑和同一临时密钥传输。两次运行均删除了云端密钥，私钥从未上传。
5. 腾讯云关机要求微信身份验证；用户完成后已选择并确认关机不收费，非普通收费关机。
