## 固定比较与汇总

主比较 C vs A；次比较 C vs B、B vs A。三项全部报告，不按显著性选择展示。每项列出双向不一致题号和人数。精确双侧 McNemar：令 b、c 为双向不一致数，n=b+c；n=0 时 p=1，否则 p=min(1, 2*sum(comb(n,k), k=0..min(b,c))/2**n)。原始 p 全部披露，同时对这固定三项给出 Holm 调整值；不因结果另增或选择比较。

沿用最初冻结协议的固定样本口径：每组报告 resolved/50，只有 harness 原始 resolved=True 计为解决；未运行、无评分、技术失败单独列出，保留原始 resolved=null，不伪造为 harness 的 False。固定50题上的“是否获得 resolved=True”二元比较为主表；同时完整报告每项仅双组均有有效评分的配对数、不一致名单和精确 p，作为缺失敏感性表，不以该表替代主表或择优引用。

每组报告：resolved、空补丁数/实际获得补丁的题数（另列缺失；无补丁产物不自动记空补丁）、首次源码编辑请求序号中位数（仅发生源码编辑的题，并列人数）、prompt/completion/总 token、缓存命中与未命中 token、请求数、usage/cache/时间推算 API 费用与统一高峰无缓存价参考、定位/编码/harness 分阶段时间、包含镜像及编排的整轮时间。服务商实扣未读到账单则标为未核验，不当作实扣。

C 每题完整报告披露条数和 R1–R4 规则计数、全回退、validator_error 原值、read_file 错误次数。定位未交付时相应字段标为未观测，不用0代替。错误次数按 tool_audit 的 read_file error 记录计数，不把同一记录在多份日志中的拷贝重复累计。

每个未 resolved 的题逐组审阅轨迹，记录：实际请求数、是否用满40次、是否存在无进展循环及证据请求号。无进展循环需要重复行动且未获得新增有效源码编辑/诊断信息的轨迹证据，不能只因用满40次判为循环；记录“是/否/证据不足/未运行”。C 另记录是否沿用定位的错误方案，使用“明确是/未见明确证据/不确定/未运行”，附定位原文与编码行为证据位置，不将相关性直接当因果。题目失败或环境异常不补跑，不改 harness 评分。

dev24 与 holdout 各自报告，另给每组24+50=74题的描述性汇总；中位数从逐题记录重算，不能平均两个中位数。开发集与holdout不合并进行确认性检验，结论只依据这50题 holdout。不同运行时段和缓存条件不解释为模型效率差异。
