# 本轮运行范围

版本 v4：只修复 Coding Agent 的纯文本 stop 终答兼容，以及增加实际源码编辑和空补丁统计。SDK 自带的纯文本内容响应处理会正常结束会话，不伪造 finish 工具调用。定位器终答校验、模型、提示、工具schema、检索、40次编码请求预算不变。

专用入口 `python -m locagent_e2e.checkpoint`，必须提供本轮 checkpoint-authorization.json。旧全量 trial 入口在本配置中拒绝执行，以免绕过前8题暂停。

执行顺序：新跑 Astropy A；零新增模型请求回放 Sympy A/B 和 Astropy B 的原始响应（分别导出diff并重新评测，要求与历史patch逐字节相同）；四组新验收全部无技术失败后，按dev24原selection_order前8题逐题A→B。定位在每题编码前生成，只有B得到定位包。8题/16次编码后必停，空补丁率>50%标记止损，<=50%也仅标记满足阈值并等待用户。后16题本轮绝不自动启动。

本轮新增模型请求共享50元账本，smoke和trial都计入。每个请求前按最大上下文和峰时价格预留，避免先超额再停止；未决/失败步骤不自动重试。返回usage计算费用，实扣账单另查。

首次源码编辑：按每次工具执行前后实际源码内容hash变化记录所属编码请求序号（从1开始）；包括终端写入、创建、删除、重命名和测试源码，.py/.c/.h/.cpp/.js等固定扩展名；不计文档/配置、被忽略且原本未跟踪的生成文件和/testbed之外的文件。工具执行边界之间写入又还原的瞬时变动不可观察。即使后续恢复原状，首次编辑序号仍保留；空补丁以最后导出的完整git diff是否为空判断，两者独立。未编辑为null，未运行不填0。

历史记录不改写。回放是适配器/工具/评测验收，不是新模型性能样本；新dev24试跑会重新调用模型，且绝不向其发送历史回答、参考补丁或harness测试补丁。仅评测进程读取已曝光dev24 evaluator数据。holdout不上传、不打开。

退出时删除云端临时API凭证；结束后由控制台执行关机不收费并确认最终状态。
