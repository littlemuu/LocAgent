## 1. 完成的修改与回归范围

原 37 题中有 29 题包含同名定义，34 题的完整题面超过 256 字符。现在保留 getter/setter、overload 与条件分支中的各个定义块；definition_id 绑定快照、实体与源代码行跨度。实体层排序保持最大 chunk 聚合和 RRF；源码预览选择匹配定义并明确提示其他定义，避免静默丢掉 setter 等证据。

检索各入口统一检查原始查询的 UTF-8 字节数，不截断、不自动改写。普通字面文本搜索保留自身的 256 字符限制。新增测试覆盖多个定义、匹配预览、Unicode 边界、抽样排除与统计规则；总计 40 项原 v8 离线测试加 8 项新增测试。历史 v1–v7 的全部旧测试套件没有重新执行，不将它们计入本次 48 项验收范围。

37 题回归验证真实 OpenHands SDK 的工具分派、子进程混合检索、证据进入下一轮会话和完成协议；在新项目目录用新环境实际耗时 37.917 秒，48 项测试耗时 16.827 秒。这不是自然语言模型表现，也不是定位质量或修复质量测量。67,404 个函数 chunk 成员保留；去重文档共 22,247,210 UTF-8 字节，最长文档 12,067 字节，最长查询 5,574 字节。

编码清单冻结的是源码文本、查询、SHA-256 与成员映射，状态为 `inputs_frozen_not_encoded`。真实 embedding 模型版本、维度、instruction 和 token 限制尚未绑定；当前运行代码有意只接受离线合成向量。恢复的旧向量资产未被伪装成这些新文档的可用缓存。

## 4. 阶段 1C：固定设计与未完成的执行条件

三组共享同一 OpenHands Coding Agent、deepseek-flash、系统提示、工具和修复预算：A 无定位包；B 当前定位；C 改进后的真实混合定位。每题 3 次独立重复，计划 450 次编码与 300 次定位；不是失败后自动重试。每次编码最多 40 请求、1M 输入/64k 输出 token、45 分钟；B/C 定位最多 4 请求、128k 输入/8,192 输出 token、14 KiB 证据。协议规定异常停止、不自动重试。

主要对比 C−B；主指标 resolve 率，固定 150 次/组分母；技术失败、缺失与超时记未解决并另外报告。次要指标为文件/函数 Recall@5、实际交付证据覆盖、技术失败与成本。三次重复先按题聚合，使用配对簇符号翻转检验、三项比较 Holm 校正、按仓库分层的配对 bootstrap 区间；第一次重复另作精确 McNemar 敏感性分析。不能用 best-of-three 替代主指标。

评测固定 SWE-bench harness 提交 `02e7a74ffd0b707aab73d203fe87bdc7c76afc8e`，在云端 Linux x86_64 Docker 上运行。可写 Coding Agent 工具、云端执行驱动、镜像 digest 与真实向量适配尚未完成；这是后续阶段的进入条件，本轮没有将只读 SDK 验证冒充成端到端修复验收。deepseek-flash 已按用户决定冻结，但服务端别名不保证权重不变，正式执行前须核验映射并记录实际模型标识，发现漂移停止。
