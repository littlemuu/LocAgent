# 阶段 1 冻结协议

本项目的问题是：**定位改进是否提升同一 Coding Agent 的端到端修复率？** 定位指标用于解释机制；最终结论以 SWE-bench resolve 率及配对不确定性为依据。本轮只完成阶段 1，未运行付费模型、真实编码、测试集定位或修复评测。

## 冻结对象与边界

- 开发集固定为原 37 题，源码、题面和快照哈希位于 `data/dev37/registry.json`；日常入口只允许读取该开发集。
- 测试集固定为 SWE-bench Verified 的 50 题。数据修订为 `c104f840cc67f8b6eec6f759ebc8b2693d585d4a`。抽样只使用 `instance_id/repo/base_commit/created_at`，未读取测试集题面、参考补丁或运行结果。原始 Parquet 仅作为封存的数据凭据，不供开发程序使用。
- 随机种子 `20261116`；先排除 37 题及保守历史曝光审计命中的 ID、PR/issue URL、基础提交；各仓库内洗牌，逐轮在仍有候选的仓库中各取一题，直到 50 题。不会因难度、跑不通或效果不佳而换题。抽样算法和输入哈希都冻结。
- “未曝光”仅指本项目可查历史中未使用；不声称模型预训练未见过公开 SWE-bench，也不把公开数据集当作秘密数据。仓库平衡抽样的结论适用于这 50 题，不能直接当成整个 Verified 500 题的官方排行榜分数。
- `freezes/stage1-lock.json` 固定运行代码、测试、配置、依赖锁、开发集、编码清单、抽样输入和脚本、测试集 ID、模型和实验设计的 SHA-256。代码版本采用内容寻址清单；不把可变工作区误称为某个 Git 提交。
- `deepseek-flash` 是用户确认的编码与定位 Agent 模型；temperature=0.2、top_p=1、thinking disabled。服务商公开映射为 DeepSeek-V4.1-Flash-1017，但别名并非不可变版本；首次正式运行前核验并记录实际返回模型标识/可得 fingerprint，发现漂移停止。不能靠冻结一个别名保证服务端权重永不变化。
- 待编码的文本已冻结，真实 embedding 的提供方、版本、维度、instruction、token 上限尚未绑定；现阶段运行代码只接受合成向量。此项是后续真实向量接入的进入条件，不能把本轮离线通过写成真实混合检索效果验证通过。

## 不查看结果的规则

1. 封存后所有调参与故障定位只使用原 37 题及合成夹具。开发入口对 `freezes/holdout-v1` 施加读取拒绝；校验命令只核验哈希。开发程序不接入封存 Parquet。
2. 在任何测试集执行之前，完成真实向量适配、Coding Agent 写入/执行工具、云端驱动、镜像 digest 和最终候选代码锁；仅用 37 题验证。阶段 1 设计锁记录当前版本，未来最终候选另立执行锁，禁止覆盖本锁。
3. 测试集运行日志、轨迹、指标和失败详情都封存到独立评测位置；全部计划执行完成或按协议停止后才一次性揭盲。不得查看早期分数后继续调参。执行人员可看不含题目与结果的资源健康状态；需要查看某题失败详情时视为揭盲。
4. 揭盲后只能报告该冻结候选的结果。任何依据这些结果的改动使这批题转为已曝光，后续验证必须重新登记新测试集；不能继续称为独立验证。
5. API 或基础设施异常停止、不自动重试。已规划的三次独立重复不属于失败重试。保留缺失试验，并在主要 intention-to-treat 指标中计为未解决；另报完整配对数和停止原因，不补挑“容易跑”的题。
6. 标准答案、参考补丁、测试补丁和历史回答只能在隔离评测器中使用，禁止进入定位或编码 Agent。修复容器不可访问网络、评测器目录、其他试验目录或评分结果。
