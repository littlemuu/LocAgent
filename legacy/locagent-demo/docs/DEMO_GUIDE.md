# 五分钟演示顺序

## 0. 开始前

在这份完整演示版目录完成 runtime 安装，再安装 `requirements-demo-test.txt` 后执行 `sh scripts/check_demo.sh`。不沿用旧服务正在使用的端口/数据目录；需要时用 `./start-local-web.command --port 8766`。默认付费关闭，无需 key。

## 1. 用半分钟交代项目

“这是在 LocAgent 上游代码图定位方法上做的本地工程化版本。输入公开 Python 仓库和问题，固定源码版本，通过图和 BM25 工具协助模型找位置，最后给出函数、行号和可核对的源码证据。”

将上游方法与本人的入口、预算授权、来源校验、轨迹和 UI 改造分开说明，避免声称整个 LocAgent 从零自研。

## 2. 展示免费入口

运行 `.venv/bin/python -B -m locagent_service.local demo`，再启动网页点「免费演示」。展示状态、结果、源码和轨迹，并明确说：“这是合成演示，只证明界面和工程入口连通，没有真实模型，也没有模型费用。”

## 3. 展示已有真实证据

打开 [两次真实案例](REAL_CASES.md) 的固定 commit 链接。itsdangerous 的时间戳验证与 nano-vllm 的 `Scheduler.cancel` 都有真实模型运行记录。指出额外候选和读取截断，不把合法完成当成已测准确率。

本轮不新跑模型。若想现场展示真实准备，可事先核实无密钥配置，演示 GitHub 下载→固定 commit→建图/BM25→待同意计划；准备免费，但需要网络。不可把准备结果称为模型答案。

## 4. 解释一次性运行设计

计划明确接收方、数据和预算；点击前精确同意计划哈希。每次请求先预留费用，收到有效 usage 后结算。未知结果保留预留，不能自动重放。这解决的是失控执行与结果可追溯问题，不是账单准确性保证。

## 5. 收尾讲限制和下一步

只有两个真实案例，缺少广泛评测；当前只有 BM25，不是任意语言或私有仓库产品；本机单用户，不是公开服务。构造函数补读与后续提示仍在隔离实验里，需真实对照后才能决定合入。后续可优先完善空缓存/跨机器安装、样本评测与依赖裁剪，不以追加调用数冒充进展。
