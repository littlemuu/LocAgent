# 检索排序、重复返回与首屏实现证据：离线修复

2026-11-16。完成新版本 `retrieval-evidence-v6`，没有真实模型请求、密钥读取、对外传输或目标仓库代码执行。旧检索器、旧索引、旧付费入口和历史结果保持原样。

## 改动

实现位于 `experiments/retrieval_evidence_v6/retriever.py`，以 `EvidenceRetriever(base, snapshot).retrieve(query)` 接入既有只读工具接口。

1. **排序**：完整实体 ID 最优先；完整限定名（例如 `Class.method`）优先于同名模块函数，跨文件同名保留歧义。短查询补充检查实体标识的完整组成部分，结合路径组件与符号名，允许显式的大小写及首尾下划线别名匹配；显示真实路径和实体拼写，不改写 `l/1`。完整组件覆盖优先于部分匹配，其余走原正分 BM25，候选池最多取 20 再选至多 5。补充匹配沿用原索引搜索范围，不偷偷加入原本排除的测试文件；显式实体请求仍允许已核验快照内的文件。
2. **去重**：非显式请求中，候选已包含子实体时移除重叠的文件／类容器；渲染时按 `(路径, 原始行号)` 去重。显式查询文件或类时仍返回该目标，不替换成其子函数。不同文件中的同名实体不会被错误合并。
3. **实现预览**：静态 AST 确定文档字符串与首个非文档语句，显示有限签名、实现前段和末段。每段带真实行号、实体全范围、实现起始行与 `read_file` 参数。长行片段、跳过的行和不完整正文均明确标注，完整源码仍通过原 `read_file` 获取。使用 Python 物理行规则，兼容 BOM、CRLF、Unicode、异步／嵌套函数和多行签名；不导入或执行目标代码。

**分页语义明确改变了内容粒度**：`next_offset` 续看的是检索预览，而非保证逐页获得整个函数／整类／整文件。提示中明确要求通过 `read_file` 读取完整范围。返回字节下降同时来自候选筛选、去重和正文省略，不能全部算作无损去重或断言模型总成本一定下降。

## 验证

- **32 项测试通过**：23 项新排序／预览／工具预算回归，加 9 项原路径检索回归。覆盖限定名歧义、组件别名、不混淆数字字母、原索引范围、容器去重、显式文件与类、空结果、异常传播、真实行号、BOM/CRLF/Unicode、长行省略、多候选分页重组、重复读取、越界、累计证据预算和收尾围栏。
- **13 次固定查询前后重放通过**：所有旧版首屏保持一致；新分页不超预算、重组等于新完整预览、没有重复的已显示源码行；实现行来自原始快照。
- **7 个实际 OpenHands SDK 离线会话通过**：通过隔离子进程调用新检索器，再执行普通读取／搜索并终答，共 21 个脚本响应。首屏与独立重放一致、累计证据不超 14,336 字节。这里使用固定脚本模拟模型决策，不是自主检索选择或质量实验，也没有真实服务请求。
- 不改目标源码，不重建历史索引；利用已验证的现有图与持久化实体索引。旧结果与准备材料在最终审计中按哈希复验。

复验材料在 `verification/retrieval-evidence-v6/`：`manifest.json` 固定查询来源；逐题 `result.json` 与 `query-*-old/new.txt` 保存前后证据；`evaluation.json` 是独立事后标签检查；`tests-final.txt`、`sdk-check.json` 是回归与实际 SDK 接线证据；`final-lock.json` 固定新版本与报告。

## 接线状态和限制

新检索器已经通过原 FileTools 和实际 SDK 工具接口验收，`offline_adapter.py` 提供绑定清单、隔离进程的只读离线入口。**旧的冻结付费入口继续引用旧版**，没有悄悄切换，也没有生成新付费授权。后续真实试跑需要基于新检索版本冻结新计划，不能继续使用旧 hash 或混算结果。

该方案仍是实体名／路径检索，不是语义正文搜索或调用图遍历；短查询的完整组件过滤可能降低部分匹配的覆盖率，大小写／下划线别名可能增加同名歧义。精确限定名优先和保留跨文件候选降低了一部分风险，尚无独立测试证明整体收益。

预览可能省略真正关键的中段实现；只保证此次非空回放中首个非文档语句进入首屏，不保证所有未来超长标识或所有相关语句都能放入一页。模型仍需依据 `read_file` 范围补读；xCDAT 与 `_parse_apply` 的后续定位问题没有被假称解决。

下一步若继续真实验证，应同模型、同题、同预算比较旧／新检索，保持其他工具与提示一致，观察准确率、补读次数及总 token，而不是仅依据预览字节减少判断收益。本次未进行该真实验证。
