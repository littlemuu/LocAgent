# 终答实体格式修复 v5（离线验收）

已修复模型可见终答契约的具体缺口，并在独立的 `experiments/finish_contract_v5/` 中接入原生循环和 OpenHands 离线适配器。没有修改已冻结的 v4 批量运行代码、原始响应、评分标签或历史结果；没有读取 Key、发送真实模型请求或续跑。新 SDK 入口明确拒绝 live 参数，公共传输仅接受 MockTransport。

## 证据与原因边界

Sisyphus #191 原生组第 4 轮返回 HTTP 200、finish_reason=tool_calls，输出 566 token，未触及 2,048 token 上限。原答案把四个纯文件路径放进 `entities`，执行器要求 `path:QualifiedName`，因此报 `invalid_entity_format`。

离线验证了更具体的矛盾：原发送 schema 对 files/entities 均只约束为字符串数组，原失败 message 能通过该 schema；新 schema 对错误的四项均报错。原始工具说明在 wire 层被替换成通用说明，收尾提示只说“文件和实体”，没有明确说明仅知文件时如何返回。这个接口缺口有直接证据；不能据此断言它是模型出错的唯一原因。

## 改动

- `finish_policy.py`：files 和 entities 有分别的描述及 pattern。entities 必须具备冒号、非空路径和非空限定名的基本形状；files 不接收实体 ID。说明使用不来自本题的通用例子，并明确“只知道文件则填 files，entities=[]；不要为了格式编造函数名”。
- `common_contract.py`：两组实际发出的 finish schema 统一替换为新版本，每次请求及最终收尾均提供同样的格式说明。将格式校验异常转成含固定原因的 ContractError，便于离线账本保留 `invalid_entity_format`，不再只剩 ValueError 类型名。
- `native_adapter.py` / `sdk_adapter.py`：接入同样的终答格式提示；原生分页、OpenHands 工具接口、检索行为和评分函数不变。修正新契约中对已有 v4 路径检索的过时描述，不再称其“尚未修复”。
- 不做响应修正：不把文件自动搬入其他字段、不猜函数名、不丢错误项、不重排答案、不降低严格评分要求。原失败回答仍是失败。

JSON Schema pattern 是基本形状约束，不宣称等价于完整 Python 标识符或所有路径安全规则；Unicode 标识符、敏感路径及目录穿越仍由既有执行器校验。也没有声称供应商会用强约束解码保证遵守 pattern。

预算不变：每组最多 4 请求、16 调查工具，单页 4,096 字节、累计证据 14,336 字节、完整请求 65,536 字节、输出 2,048 token。没有新增终答字符硬截断或修复轮次；异常仍停止。

## 离线验证

59 项测试通过，包括：历史错误“旧 schema 接受、新 schema 拒绝”、file-only / 空实体终答、函数/类/嵌套与 Unicode 限定名、重复/超项/错误类型、路径安全、未知但格式合法的预测保留、null 扩展兼容、两组 schema 一致、最终轮仅允许 finish、输出截断拒绝、原始回包落盘及停止后不可重试、live 入口关闭，以及读取/检索/评分回归。

在 Sisyphus 固定源码与真实引擎/SDK 上完成两种场景、两组共 16 次 mock 请求：file-only 正常终答，两组均完成；注入原历史错误响应，两组均在第 4 轮停止，账本保留原回包及准确原因，未结算预留为 0。OpenHands 的 locagent_retrieve 工具仍注册，脚本只测试收尾，不查询检索；这不是模型自主行为实验。首轮无检索工具注册的冒烟结果另行保留，最终验收用注册检索工具的 integration-v2。

重新序列化并保守估算 148 条历史请求，新格式提示加入后的最大请求上界 34,919 字节，小于 65,536。它是已有轨迹的离线大小检查，不是未来模型轨迹的保证。旧准备清单和真实结果锁全部逐文件复核通过。

## 当前交付与后续边界

交付的是经过离线验收的新终答协议和两套适配器。已停止的 v4 真实批量入口没有被原地修改；新付费批量入口尚未冻结或启用，不能复用已消费的一次性授权。正式采用 v5 时还需让新的批量 guard、SDK 调用和原生 worker 都引用此版本，并把新源码哈希、最新 201 次累计请求及费用账本绑定到新的明确范围。这是运行接入待办，不是用户已授权续跑。

建议先以 Sisyphus 单题两组验证新格式（最多 8 次请求、17 元保守上限；仍需新运行方案和授权）。若之后仅补失败题及剩余 17 题，将形成 v4/v5 两个版本的开发结果，必须分开报告；若要求统一版本的完整 37 题比较，则需要另行批准从头运行，不能把旧 19 对直接拼作同一版本成绩。真实模型是否更遵守新约束尚未验证。

证据在 `verification/finish-contract-v5/`：`tests-final.txt`、`integration-summary-v2.json`、`saved-wire-screen.json`、`history-integrity.json`；代码和验证材料最终绑定在 `repair-lock.json`。
