## 评分规则

新增独立版本 `localization-metrics-v1`，历史评分器和结果保持原样。令 G 为唯一参考实体集合，P 为有序预测，h 为 P 前 k 项中的唯一命中数，k 取 1、3、5：

| 名称 | strict 定义 | 解释 |
|---|---|---|
| Acc@k | `h == min(k, |G|)` | 前 k 的理想命中覆盖条件，不能当作“至少命中一个” |
| Recall@k | `h / |G|` | 对全部参考实体的召回 |
| Hit@k | `h > 0` | 单独报告至少一次命中 |

`strict` 保留精确实体 ID；`upstream_reference` 将两边的 `.__init__` 归一到类、归一后去重再取 top-k，并使用 `min(|G|, 10)` 参考分母。后者是明确标注的兼容口径，不能与精确实体分数混报。

现有 `experiments/locbench_dev/scoring.py:official_reference` 只归一参考答案，没有同样归一预测；类/构造函数还可能在归一后重复计数。新评分模块对称归一、去重并拒绝非法提交，覆盖相关回归。旧 strict 评分器原有 P/R/F1/MRR，不能把这些字段改名为 Acc@k。

130 题标签统计：空标签 0、原始重复 0、含构造函数 18、唯一参考实体超过 5 个的题 10、超过 10 个的题 0。因此这 10 题的 Recall@5 天花板小于 1，Acc@5=1 也不代表完整定位。不能为了满分删掉这些题。

模拟结果禁止质量评分；未完成运行的质量字段为空，单列技术失败/未运行。若统计计划总分母上的失败计零，必须另列这一口径，同时报告完成率与完成题定位分数，不能把基础设施失败描述为模型找错。

## 两类对照不能混同

已验证的是“同一 OpenHands，仅检索工具可用性不同”的模拟接入。要比较“原始 LocAgent 与当前 harness”，还存在以下可确认差异：

| 项目 | 本地 LocAgent 连通性探针 | 当前 OpenHands |
|---|---|---|
| 正文检索 | `search_code_snippets` 已声明，但正文 BM25 后端未接入 | 实体 ID BM25 已从新缓存读取 |
| 分页上限 | 默认 8,192 JSON 字节 | 4,096 JSON 字节 |
| 证据预算 | 默认总 24,576，含 4,096 收尾控制，约 20,480 源码预算 | 14,336 源码 JSON 字节 |
| 工具次数 | 每响应最多 16；3 次调查可达 48 | 每组累计 16 |
| 终答候选 | 默认最多 20 | 最多 5 |
| 传输与账本 | 本轮脚本 provider，尚未接共同真实传输准入 | 已通过 MockTransport 与持久化账本验证 |

LocAgent 的 equal_source_budget 模式可把候选/重读预留计入后达到 14,336，但本轮探针用默认配置，没有完成共同契约的实测。它也未用共同 wrapper 强制输出 token 上限。不能把实体索引假装正文索引，或称上述探针已经公平对齐。

缓存桥只接入本轮离线入口；旧真实批处理仍绑定旧引擎，正常门禁拒绝新代码。下一步须补正文索引、统一累计预算/分页/top-k/收尾与输出限制，接共同持久化准入，再冻结新可执行计划。完整系统对照允许工具/提示设计作为处理差异，但应同题、同模型、同源码信息范围和预算，并明确不能据此归因“检索带来收益”。
