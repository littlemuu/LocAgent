## 系统版本和公平口径

系统 A：LocAgent 图工具 + physical-line80 正文 BM25（适配版）。系统 B：OpenHands 基础文件工具 + 实体 ID BM25（适配版）。不是上游原版对照，也不是“只差检索开关”的实验。

`proposal.json` 冻结现有 41 个适配 Python 文件哈希、readonly_agent runtime hash、v4 引擎 manifest hash、OpenHands 1.62.0 依赖锁及共有契约；`runtime-cases.json` 固定五题的题面入口/快照/基准提交/索引证明哈希。模型输入仅从这些 source-only 条目构造，gold 绑定和语义说明只在 `scoring-only/`，不用于生成查询或提示。

拟固定 `deepseek-flash`、temperature=0、thinking disabled。同题两组使用同一原题全文和 Python 源码清单；每题每组最多 4 请求、累计 16 次调查工具、14,336 字节证据、4,096 字节单页、65,536 字节完整请求、2,048 输出 token。最后一次请求或证据预算耗尽只允许 finish；保留“预算强制收尾/模型主动提前终答”的区别。相同最大预算不保证两系统实际信息量和轮数相同。

每题每组新进程、缓存、会话和分页游标；禁止跨题记忆、gold 回馈和结果导向补查。题序固定如表，先运行的组按 A/B/A/B/A 交替（五题无法完全平衡），记录顺序与缓存命中，不推断缓存来源。预算/结果按固定五对计数。

## 评分与故障分类

采用已冻结 scorer 的 strict 主口径，按终答实体顺序计算 k=1、3、5：`hits=|前k个候选 ∩ 全部gold|`；`Acc@k = 1[hits=min(k, gold数量)]`，`Recall@k=hits/gold数量`，`Hit@k=1[hits>0]`。当前五题每题单 gold，因此三个指标在同一个 k 上等价；仍须看首次命中排名，不能包装成三项独立证据。secondary upstream_reference 可单列，不能与 strict 混报。

不删除错误候选、不凭 gold 纠正限定名、不自动把类属性变成函数。语法正确但不存在的实体算定位错误；空列表是有效未命中。重复实体、超项、错误 JSON 或非法路径按终答协议失败处理。完整函数名精确匹配，strict 不剥离 __init__。标签为空或待审不得静默移出分母。

分别报告完成率、完成题质量及固定计划分母（每组五题）的失败/未启动计零结果，并列出完成、技术失败、未启动数量。技术失败分为输入/哈希、授权/重复、网络/超时/HTTP、用量/预算、输出截断/协议、工具执行、非法终答；有效终答定位错不叫基础设施失败。

第一项技术异常停止整个批次，不自动重试、不自动跳过后续题继续；保留此前结果与未启动项。评分在答案冻结后离线执行。已有评分 10 项回归本轮通过；尚未做新的五题批量故障模拟。
