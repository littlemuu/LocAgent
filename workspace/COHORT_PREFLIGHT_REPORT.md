## 全量技术检查及修复

全量 22,897 个题内源码文件引用、269,624,775 字节均与冻结哈希相符。130 题来自同一记录的数据集 revision；逐题题面所属任务、基准提交、源码计划及标签基准提交一致。没有重新从网络验证远端仓库或数据集。

隔离的新正文索引共 106,139 块，磁盘文件约 512.6 MB。两个受限并行构建进程使用空白临时缓存、显式源码清单和离线防护；每题重新创建源码/索引对象，逐题构建后重新加载并核对全部 corpus。没有运行 setup.py、导入目标模块、调用模型或执行目标测试。

确认并处理了三个入口问题：

1. 原入口写死 SQLGlot。新增 `experiments/cohort_preflight/entry.py` 和严格字段运行条目，按 case ID、题面哈希、基准提交、源码快照、实体索引、正文索引及证明文件绑定；错配题目索引、额外 gold 字段、篡改文件及符号链接被拒绝。
2. 原正文分块使用 `splitlines()`，会把字符串内的 U+2028/U+0085 等当作源码换行。新 `physical-line80-v2` 仅按 CR/LF/CRLF 计行，保留原文；原生正文输出直接呈现经过证明的块，避免旧 LF 切片再次改变行号。人工样例复现并验证修复；本批源码扫描未发现此类 Unicode 分隔符，因此没有声称此前真实结果受此问题影响。
3. 2 道题的完整题面超过 SDK 原先 8 KiB 限制，最大为 12,537 字节。新模拟运行器保留完整题面，采用两系统共同的 65,536 字节精确 wire 请求门禁；没有截断题面。人工长题面的实际 SDK → 模拟传输测试通过。全量首请求模板替换预检的最大保守上界为 27,281 字节；原生仓库名前缀另预留 512 字节。这个结果不能保证后续所有轨迹都不耗尽上下文预算。

新增批次控制器对超时、非零退出、异题结果和超额度结果停止后续题目，不自动重试；保留已完成、失败、未启动三个计数。评分汇总要求显式运行模式和固定题目集合，不再凭 SDK 的 completed 状态猜测是真实模型结果；模拟成绩为空，完成题分数与计划分母失败计零口径分列，缺 gold、重复结果和集合外结果不得静默丢弃。

旧 v4 引擎、readonly_agent harness、此前适配器、索引和 gold 文件均未改写。新产物位于 `verification/cohort-preflight-v1/`。

## 比较方案与隔离

准确名称为：

- **LocAgent 图工具 + physical-line80 正文 BM25（适配版）**。
- **OpenHands 基础文件工具 + 实体 ID BM25（适配版）**。

两者共享题面、冻结 Python 源码范围、模型参数和预算，但提示、工具能力、图遍历、检索字段及排序不同。固定行分块不是上游 EpicSplitter，共同预算也修改了原生执行协议；因此这是适配后的完整系统比较，不能称未修改的“原版 LocAgent vs harness”，也不能直接归因检索收益。若要测检索增益，应另用同一 OpenHands 循环、仅改变检索可用性的配对方案，不与本方案成绩混合。

共享限制仍为每组最多 4 次请求、累计 16 次调查工具、14,336 字节证据内容、4,096 字节单页、2,048 输出 token，最后请求只允许 finish，files/entities 各最多 5。相同信息上限不等于实际信息量或工具行为相同；每条真实轨迹仍需单独报告完成率、失败、用量和分数。

最新 `pilot-v2` 用 Loguru、SQLGlot 各两组，独立进程、临时缓存、账本、源码对象和 SDK 会话。原生两题均实际触发正文回退，两组均正常收尾，共 16 次模拟响应。旧 `pilot` 的 16 次响应也保留；本轮成对模拟共 32 次脚本响应，长题面单测另有 1 次。没有自主模型选择或定位质量结论。

运行输入与评分材料分目录。模型可见工具仅访问明确的源码快照；运行条目拒绝额外评分/补丁字段。没有把程序审查结果或 gold 传给检索查询。两题使用的查询来自原题面；已检查请求中没有混入另一题题面。源码缓存及 body 目录按题独立，即使源码相同也不复用会话/游标。

本地分组仍为开发 37、test 93，仓库集合无交集。发现 2 组不同题共享相同源码快照，共 128 个不同快照；它们不是自动重复题，仍须按题面审查，并在统计中考虑仓库/提交相关性。
