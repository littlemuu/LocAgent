# 不同信息状态下，普通工具和 LocAgent 能补什么

2026-11-13（北京时间）。本轮检查了 **7 个真实轨迹检查点、1 个构造状态、22 条离线路径**。复用 6 条已有检索结果，没有新增模型请求或检索引擎调用。新操作仅通过已审阅的普通文件工具读取固定源码；未执行源码、读取凭据或修改检索策略。2,751 个历史/生产/冻结文件哈希保持不变。

结论是：**检索最明确的潜在作用，是把没有文件位置的符号线索直接变成正文，或把分散的词映射到少量相关实体。已有文件/行号或已有正文时，它未必减少工具步骤；在模糊自然语言发现和大文件返回上，当前接入还有明显缺口。** 这是能力和成本代理的观察，不是对模型动机的因果解释。

## 公平口径

- 每条路线从相同检查点、相同源码出发，独立使用该检查点**实际剩余**工具次数和证据字节：初始 16 次/14,336 字节，Loguru 文件已知 14 次/10,210 字节，SQLGlot 已知符号 14 次/12,277 字节，正文已知 12 次/8,990 字节；每页最多 4,096 字节。
- 每个分页也计一次工具调用；搜索与后续读取共用同一个剩余预算。表中为完整 JSON 工具回包的 UTF-8 字节，包括分页元数据，**不是模型 tokens、价格、时延或总体计算成本**。未计算索引构建成本；重用缓存不等于检索运行没有成本。
- 普通路线不是只搜一次长句：提供题面短词搜索、按可见命中位置读取、已知文件直接读取，以及小仓库列目录后逐文件读取。LocAgent 沿用已有真实或有来源的查询，不注入参考实体名。
- 通用定位读取启发式：搜索完可交付页面，优先选查询词的首个 `def` 命中，否则首个普通命中，从该行向后最多读 40 行；已知定义直接取上下文可见定义行。没有拿 AST 或标签确定读取终点。这个启发式不是最优路线，会漏掉命中前面的函数头。
- 补充的 `retry`/`token` 路线是在初步比较后，由分析者从原题挑短词，再读取所有可见命中文件；已单独冻结来源和步骤，**属于事后补充，不是独立预注册结果**。它避免把普通工具局限在较差的长句或失败关键词上。
- 多个工具可在一次模型响应中请求，工具步数不等于模型请求数。既有字节不重复收费；正文已知状态的零成本只指“无需再取该函数”，不表示整题已经解答。

额外保存了完全相同长查询的字面搜索（两个跨文件例子均空）及真实首轮 `webhook`、`share_token` 的普通路线。它们用于说明接口差异或还原曾经的查询，**不用于断言普通搜索无能**。合理拆词或目录读取都能改进结果。

整题原文不直接比较：Loguru 999 字符、SQLGlot 1,386 字符，都超过两种查询接口的 256 字符限制。这里的 `traceback`、`SET TAG` 是有来源的短词/短语，不称为全文语义查询或 title-only。

函数完整性以固定源码 AST 跨度及逐行内容校验；函数数量只是覆盖描述，不是质量分数。返回了更多函数可能是噪声；返回较少也可能遗漏必要依赖。LocAgent 当前实现检索实体 ID，不做正文语义检索或调用图展开，跨文件出现多个实体不能称为已完成调用链推理。

## 可证伪假设与优先级

| 假设 | 当前支持/反例 | 能区分它的后续实验与否证条件 |
|---|---|---|
| **H1：位置未知时，实体检索更可能减少取正文步骤** | 构造符号状态 2 步 vs 1 步；真实已知位置状态 1 vs 1；正文已知 0 vs 1 | 优先离线寻找自然“已见符号、未见路径”检查点，冻结前缀和剩余预算。先比较最短可见证据路线，再另行申请自主选择试验。若真实状态中搜索一页即交付完整函数，或检索需多页/歧义消解，少步假设可被否证。若有少步空间但模型仍不选，只否证该状态下“更可能选择”，不否证能力 |
| **H2：多词实体线索可使检索更快交付跨文件核心逻辑，但未必减少字节** | 两个实际自主选择正例有 1 步核心函数；普通 `retry`/`token` 需 4 步；文档例中普通路线更少字节 | 选真实大仓库的跨文件开发状态，先固定题面可导出的词及普通路线，比较同等核心证据覆盖与完整任务缺口。若普通搜索/读取同样一步足够，或检索只覆盖部分核心逻辑，少步优势不成立；若只在自写短文件上成立则不能推广 |
| **H3：已知路径/正文减少了额外检索的信息价值** | SQLGlot 实测工具可一步读正文；已有正文无需再检索。说明调整后的两次选择仍为 read+search | 自然状态按路径已知与正文已知分别分层，不能只通过删除路径伪造“自然对照”。若仍有重要跨文件缺口而检索能补充，或模型在正文已知时检索新依赖，则“检索只会重复”解释被否证。当前仅就目标函数正文成立 |
| **H4：自然措辞/大文件与当前 ID 检索的匹配有限** | Loguru traceback 无候选，已知文件两种路线均耗尽剩余字节；SQLGlot SET TAG 返回相关类型而非目标函数 | 优先做免费发现路线检查：只用当时题面/工具线索，预先固定查询与停止规则，记录能否逐步到达目标、首次完整证据成本。若找到短而稳定的非 oracle 路线，当前局部失败不能推广；模型从未看过这些离线失败，不能说它因此放弃 |

**建议顺序：**先用现有免费记录寻找自然“已知符号、位置未知”或“跨文件缺口尚未补齐”的状态；若没有，准确报告没有，不拿当前 SQLGlot 再反复改说明。随后优先验证 H1/H2 的证据与成本空间，最后再规划模型自主选择试验。已知正文状态可作为低新增信息需求的参照，但不预设“正确动作必须不检索”。任何新真实调用另列数据、模型、请求数和费用范围；本轮未启动。
