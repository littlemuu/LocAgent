## 4. 首题内部异常及离线复现

**已读到的事实。** 冻结 `calibration/policy.py` 的 `violations()`（179–211 行）遍历全部 AST 实体，195 行用裸名称正则扫描整段 answer；路径和命令中的词也会命中。`calibrate()`（214–236 行）生成保守三段后，在 229 行再次调用同一检查并 assert；这个 assert 没有转换为可交付的结果。

真实 SDK `ConversationErrorEvent` 保存了完整错误：

```text
R1_body_incomplete_unmarked:sympy/ntheory/factor_.py:core
R1_body_incomplete_unmarked:sympy/polys/polyutils.py:_parallel_dict_from_expr
R1_body_incomplete_unmarked:sympy/printing/python.py:python
```

由此终答结果为 `finished=null`、`status=failed`，`diagnostic-audit.json` 也未成功生成非空记录。冻结 Coding Agent 没有收到任何定位包。完整真实证据位于 `evidence/run/trial/sympy__sympy-21379/`。

**推断与已复现的机制。** 路径片段 `sympy/core/...` 被误认成另一文件的 `core()`；回退验证命令中的 `python` 也会撞上同名实体。校验器把跨模块裸名称扩展为新实体，但回退内容只给原候选实体追加未读完标签，导致再次验证不能通过。零 API 最小示例已复现“只引用 core 目录也触发未读 core 函数”的同类 AssertionError，见 [validator-defect-reproduction.json](validator-defect-reproduction.json) 和 `control/reproduce_validator_failure.py`。它是合成代码缺陷复现，不是实际 C 再跑。

**未核验点。** 没有修改、修复或付费重试冻结 v8；没有验证修复后能否完成任何真实开发题，也没有验证剩余题是否会遇到相同缺陷。原 22 项和新 22 项测试在云端都通过，但覆盖不足以发现本次真实仓库中的名称碰撞。下一步若要修复，应另起冻结版本并增加目录名、验证命令名、跨模块同名实体、项目符号与前置未读标签的用例；本轮未实施。
